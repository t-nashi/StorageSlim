# StorageSlim サンプル画像

動作確認・回帰確認に使う画像を用途別にまとめています。
実行手順は `docs/verification-guide.md` を参照してください。

## 一覧

| ディレクトリ | 目的 | 出力形式 |
| --- | --- | --- |
| `input/` | 基本的な形式別の読込確認 | 任意 |
| `webp-limit/` | WebP の寸法上限 16,383 px の境界 | WebP |
| `jpeg-limit/` | JPEG の寸法上限 65,500 px の境界 | JPEG |
| `avif-limit/` | AVIF の寸法上限 65,535 px と警告しきい値 32,768 px の境界 | AVIF |
| `avif-limit/viewer-check/` | ビューア側の上限確認（アプリの出力ではない） | - |
| `animated/` | アニメーション GIF のリサイズ | GIF |
| `size-increase/` | 出力が元より大きくなるケースの表示 | JPEG |
| `decode-limit/` | デコード時のメモリ上限 | 任意 |

## 境界値の考え方

寸法の境界テストでは**細長いストリップ**を使っています。正方形にすると、エンコーダの寸法上限に到達する前にデコード時のメモリ上限で弾かれてしまい、何を検証しているのか区別できなくなるためです。

例: `16383 x 16383` は 268 メガピクセル = 約 768 MB となり、既定のデコード上限 512 MB を超えます。`16383 x 64` なら約 4 MB で済み、寸法上限だけを単独で検証できます。

## ファイル

### webp-limit/

| ファイル | 寸法 | 期待結果 |
| --- | --- | --- |
| `wide-16383x64.png` | 16383 x 64 | 成功 |
| `wide-16384x64.png` | 16384 x 64 | 失敗 |
| `tall-64x16383.png` | 64 x 16383 | 成功 |
| `tall-64x16384.png` | 64 x 16384 | 失敗 |

### jpeg-limit/

| ファイル | 寸法 | 期待結果 |
| --- | --- | --- |
| `wide-65500x64.png` | 65500 x 64 | 成功 |
| `wide-65501x64.png` | 65501 x 64 | 失敗 |

libjpeg の `JPEG_MAX_DIMENSION` は 65,500 です。規格上の 65,535 まで書くと、libjpeg 系のソフト（ImageMagick / IrfanView など大多数）で開けないファイルになります。

### avif-limit/

| ファイル | 寸法 | 期待結果 |
| --- | --- | --- |
| `threshold-64x32768.png` | 64 x 32768 | 成功・警告なし |
| `threshold-64x32769.png` | 64 x 32769 | 成功・**警告あり** |
| `tall-64x65535.png` | 64 x 65535 | 成功・警告あり |
| `tall-64x65536.png` | 64 x 65536 | 失敗 |
| `wide-65535x64.png` | 65535 x 64 | 成功・警告あり |
| `wide-65536x64.png` | 65536 x 64 | 失敗 |

`viewer-check/` の 2 ファイルは ImageMagick で直接生成した AVIF で、アプリの出力ではありません。ビューア側の上限（libavif の 32,768 px）を確認するためのものです。

### animated/

| ファイル | 内容 |
| --- | --- |
| `offset-frames.gif` | 200x120 のキャンバス。2 コマ目以降が `96x66+10+20` のような**部分矩形フレーム**を持つ |

`input/sample-animated.gif` は全フレームが全面（`640x360+0+0`）なので、部分矩形フレームの不具合は検出できません。リサイズの回帰確認にはこちらを使ってください。

### size-increase/

**形式変換で増えるもの**（項目 5・JPEG 出力で使用）

| ファイル | PNG | JPEG(q80) | 増減 |
| --- | --- | --- | --- |
| `flat-320x200.png` | 925 B | 1,799 B | **+94%** |
| `gradient-256x256.png` | 1,129 B | 1,269 B | +12% |

平坦な領域が多い画像は PNG が極端に得意なため、JPEG へ変換すると増えます。これはバグではなく正常な結果です。
なおこの 2 つは **PNG → PNG の再エンコードでは縮む**ため、オリジナル維持の確認には使えません。

**同一形式の再エンコードで増えるもの**（項目 5-2・オリジナル維持で使用）

| ファイル | サイズ | 増える理由 |
| --- | --- | --- |
| `indexed-320x200.png` | 874 B | 8 色のパレット PNG。本アプリは RGBA8 で書き出すため必ず膨らむ |
| `lowquality-640x480.jpg` | 2,225 B | 品質 30 の JPEG。既定の品質 82 で再エンコードすると膨らむ |

こちらは元ファイルコピーへのフォールバックが働くことの確認に使います。

### decode-limit/

| ファイル | 寸法 | 必要メモリ |
| --- | --- | --- |
| `huge-24000x8000.png` | 24000 x 8000 | 約 549 MB (Rgb8) / 732 MB (Rgba8) |

192 メガピクセルあり、既定のデコード上限 512 MB を超えます。ファイル自体は 584 KB です。
