## 1. プロダクト概要

**StorageSlim** は、画像ファイルをローカル PC 上で圧縮・リサイズ・形式変換する Tauri 製デスクトップアプリです。

- 対象 OS: Windows / macOS
- 用途: クラウドへアップロードする前の写真・画像を手元で最適化する
- 対応形式: GIF / JPEG / PNG / WebP / AVIF / HEIC / HEIF
- 主な機能: 一括変換、リサイズ、品質調整、メタデータ削除、フォルダ構造の維持

**名前の意味**: `Storage`（保存領域）+ `Slim`（細く / 軽く）。
「保存容量を削る」がプロダクトの本質です。

アプリ内のヘッダは以下の構成です（アイコンと世界観を揃える対象）。

```
StorageSlim              ← 製品名（h1）
画像最適化ワークベンチ      ← 説明文
```

## 2. デザインシステム（確定事項）

変更する場合は意図的に行ってください。既存の UI と揃えるために決めた値です。

| 項目 | 値 | 備考 |
| --- | --- | --- |
| キャンバス | 1024 × 1024 | `tauri icon` の推奨入力サイズ |
| 背景 | `#0E2029` | アプリのパネル背景に近い暗色 |
| 背景の角丸 | `rx = 228`（辺の約 22%） | Windows / macOS の中間的な値 |
| メイングラデーション | `#3BA9FF` → `#34D97B` | 45 度（`x1=0 y1=0 x2=1 y2=1`） |
| アクセント（ミント） | `#6BF5B4` | 「結果」「到達点」を示す要素に使用 |
| ハイライト（白） | `#EAFFF4` | 矢印・線などの前景要素 |

グラデーションはアプリ内の実行ボタンや進捗バーと同じ配色です。

### SVG の共通テンプレート

```svg
<?xml version="1.0" encoding="UTF-8"?>
<svg xmlns="http://www.w3.org/2000/svg" width="1024" height="1024" viewBox="0 0 1024 1024">
  <defs>
    <linearGradient id="brand-gradient" x1="0" y1="0" x2="1" y2="1">
      <stop offset="0" stop-color="#3BA9FF"/>
      <stop offset="1" stop-color="#34D97B"/>
    </linearGradient>
  </defs>
  <g id="icon">
    <rect id="bg-plate" x="0" y="0" width="1024" height="1024" rx="228" fill="#0E2029"/>
    <!-- ここに図形 -->
  </g>
</svg>
```

### ファイル作成のルール

- `<symbol>` / `<use>` を使わず、すべて実体のパスにする（Illustrator でクローンにならないように）
- 各パーツに意味のある `id` を付ける（Illustrator のレイヤー名になる）
- グラデーション定義は 1 つにまとめる
- ファイル冒頭のコメントに寸法・比率・設計意図を残す

## 3. 技術要件

最終成果物は 1024×1024 の PNG 1 枚です。そこから全サイズを自動生成します。

```bash
npm run tauri icon <1024pxのPNG>
```

このコマンドで以下が `src-tauri/icons/` へ生成されます。手作業は不要です。

- `32x32.png` / `128x128.png` / `128x128@2x.png`
- `icon.ico`（Windows）/ `icon.icns`（macOS）
- `Square30x30Logo.png` 〜 `Square310x310Logo.png`、`StoreLogo.png`（Windows Store）

現在は Tauri のデフォルトアイコンのままです。

## 4. 評価基準（最重要 / これまでの検討で確立した判断軸）

**この節が引き継ぎの中核です。** 多くの案がここで落ちました。

### 4-1. 32px で成立するかが最大の関門

タスクバー・トレイ・エクスプローラでは 16〜32px で表示されます。ここで潰れると何のアプリか分かりません。

- 線は 72px グリッド換算で 3px 以上（1024 換算で約 43px 以上）
- 構成要素は 3 つまで
- 塗り面積が大きい形ほど小サイズで残る
- 破線・細い輪郭・小さい円は 32px で消える

**確認方法**: 32px に縮小してから拡大表示し、形が判別できるか見る。

```bash
magick icon.svg -resize 32x32 -filter point -resize 400% check.png
```

### 4-2. 不透明度で階層を作らない

初期案では下段ほど `opacity` を下げて逓減を表現していましたが、**下段が背景へ沈んで読めなくなります**。

代替手段は 4 つあります。

- 幅や厚みだけで階層を作る
- 縦グラデーションで下を明るくする
- 最小要素をミント `#6BF5B4` で抜く
- 下へ行くほど厚みを増す（凝縮の表現）

### 4-3. 既存アイコンとの衝突を避ける

| 形 | 衝突先 | 該当した案 |
| --- | --- | --- |
| ▼型に並ぶ逓減バー | フィルター / 絞り込み | 逆三角形の逓減レイヤー |
| 角丸枠 + 下向き矢印 | ダウンロード / 保存 | F 案 |
| 左右対称の砂時計 | 待ち時間 / 処理中 | E 案（対称版） |
| 3 連の下向きシェブロン | スクロールダウン | 三段テーパー |

砂時計については、**上下を非対称にする（上を大きく、下を小さく）と一方向の流れが生まれ、「大きいものが小さくなる」と読める**ようになり、待ち時間の連想が弱まりました。

### 4-4. 平行マージンには縦横比を揃える必要がある

2 つの三角形の間隔を一定に保つには、**両者の `幅 ÷ 高さ` を一致させる**必要があります。傾きが揃わないと隙間が変動します。

実例: 上 749×440（比 1.70）と下 495×338（比 1.46）では、隙間が 46〜59px と変動していました。比率を 1.72 に統一したところ、指定値ちょうどの一定マージンになりました。

配置方法は、上の三角形の右辺を法線方向へ一定量オフセットした線上に、下の三角形の頂点を置きます。

### 4-5. 中央揃えの確認

図形群のバウンディングボックスを 1024×1024 の中央に置きます。見落としやすく、実際に 28〜56px ずれていた案が複数ありました。

## 5. 検討済みモチーフと結論

約 60 案を 11 ラウンドで検討しました。同じ轍を踏まないよう結論を残します。

### 有力（生き残っている方向）

| 方向 | 内容 | 評価 |
| --- | --- | --- |
| **円盤の逓減** | ストレージの円盤が下ほど小さく/薄くなる | ストレージ用途が伝わり、32px 耐性も高い |
| **ドラムの圧縮** | 円筒の上部が実体、中間が半透明、下部が圧縮後 | 前後の対比が明快。要素数がやや多い |
| **非対称の▼▲ペア** | 大きい▼と小さい▲を斜めにずらす | 抽象的でモダン。用途は伝わりにくい |
| **面取りブロックの逓減** | 六角形ブロックが段階的に小さくなる | 定番アイコンとの衝突がない |

### 検討して見送った方向

| モチーフ | 見送り理由 |
| --- | --- |
| 画像フレーム + 圧縮矢印 | 要素が多く小サイズで団子になる |
| S モノグラム（文字ベース） | 他の S 始まりアプリと埋もれる |
| 羽根（軽さの比喩） | 画像ツール感がない |
| トリミング枠 | 切り抜きツールと誤解される |
| 面積の対比（破線で前後） | 破線が 32px で消える |
| SSD チップ | ピンが細く小サイズで潰れる |
| 箱を上下から圧する | 圧する板が細く沈む |
| 3 要素のジグザグで S | 3 つ目が離れて「散らばった破片」に見える |
| 一体型の円筒 + 分割線 | 分割線が 32px で消え、ただの円筒になる |
