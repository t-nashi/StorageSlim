# StorageSlim 出力形式対応マトリクス

最終更新: 2026-08-12  
ステータス: MVP 開発中

## 1. 目的

入力形式ごとの出力可否を定義します。UI の出力形式制御と処理時のバリデーションは、この内容に合わせます。

## 2. 記号

- `可`: 初期版で許可する
- `不可`: 初期版では許可しない
- `制限付き`: 入力認識や一部処理は行うが、現ビルドでは制約がある

## 3. 対応マトリクス

| 入力形式 | オリジナル維持 | GIF | JPEG | PNG | WebP | AVIF |
| --- | --- | --- | --- | --- | --- | --- |
| GIF（静止画） | 可 | 可 | 可 | 可 | 可 | 可 |
| GIF（アニメーション） | 可 | 可 | 不可 | 不可 | 不可 | 不可 |
| JPEG / JPG | 可 | 可 | 可 | 可 | 可 | 可 |
| PNG | 可 | 可 | 可 | 可 | 可 | 可 |
| WebP | 可 | 可 | 可 | 可 | 可 | 可 |
| AVIF | 制限付き | 制限付き | 制限付き | 制限付き | 制限付き | 制限付き |
| HEIC | 制限付き | 可 | 可 | 可 | 可 | 可 |
| HEIF | 制限付き | 可 | 可 | 可 | 可 | 可 |

## 3.1 寸法上限

幅・高さそれぞれに独立して適用する。判定はリサイズ後の寸法に対して行う。

| 出力形式 | 上限 | 挙動 | 根拠 |
| --- | --- | --- | --- |
| WebP | 16,383 px | 失敗 | libwebp `WEBP_MAX_DIMENSION` |
| JPEG | 65,500 px | 失敗 | libjpeg `JPEG_MAX_DIMENSION` |
| GIF | 65,535 px | 失敗 | 寸法フィールドが 16bit |
| AVIF | 65,535 px | 失敗 | rav1e の受付上限 |
| AVIF | 32,768 px | 警告付き成功 | libavif 系デコーダの既定上限 |
| PNG | なし | - | 寸法フィールドが 32bit |

`書ける寸法` と `読める寸法` が一致しない点に注意する。

- JPEG: 規格の SOF フィールドは 65,535 まで表現できるが、libjpeg は 65,500 で切っている。65,501〜65,535 で書くと libjpeg 系のソフトで開けない。
- AVIF: rav1e は 65,535 まで書けるが、libavif は既定で 32,768 までしか読まない。32,769〜65,535 の AVIF は Chrome / Firefox / Windows / IrfanView などで開けない。

そのため JPEG は読める側 (65,500) を採用して失敗させ、AVIF は書ける側 (65,535) で失敗、読める側 (32,768) は警告としている。AVIF のファイル自体は仕様上正常で libheif 系では読めるため、失敗扱いにはしない。

## 3.2 デコード時のメモリ上限

寸法が上限内でも、デコードに必要なメモリを確保できなければ処理できない。

- 既定 512 MB (`image` クレートの `Limits::default().max_alloc` と同値)
- `品質調整・その他` から 64-8192 MB の範囲で変更可能
- 必要量の目安は `幅 x 高さ x 3〜4 byte`
- 上限を超える入力は、処理前に入力一覧へ必要量を表示する
- HEIC / HEIF は `heif-oxide` でデコードするため適用外

## 4. 形式別補足

### GIF

- アニメーション GIF はアニメーション保持を前提にする。
- アニメーション GIF は GIF 出力のみ許可する。
- アニメーション GIF から非アニメーション形式への変換は不可とする。
- GIF のフレームはキャンバス全体ではなく部分矩形 (`left` / `top` / `width` / `height`) で格納されうる。リサイズ時はフレーム単体ではなく、キャンバスへ合成してからキャンバスごとリサイズする。
- 廃棄方法 (`DisposalMethod`) は `Background` で該当矩形を透明化、`Previous` で描画前の状態を復元する。
- 出力は合成済みの全面フレームとする。差分最適化が効かないため、出力サイズが元より大きくなる場合がある。
- 透過インデックスは元フレームから引き継がない。パレットが変わる再エンコード後は意味が壊れるため。

### AVIF

- 出力形式として AVIF を提供する。
- AVIF 入力は拡張子・形式として認識する。
- 現ビルドでは AVIF 入力の読込処理を一時制限している。
- AVIF 出力は処理時間が長くなりやすいため、速度確認は release ビルドで行う。
- AVIF speed プリセットは MVP では UI に出さない。
- 32,768 px を超える AVIF は生成できるが、libavif 系デコーダの既定上限を超えるため主要ビューアで開けない。失敗ではなく警告として扱う。

### HEIC / HEIF

- 入力読込に対応する。
- JPEG / PNG / WebP / AVIF / GIF への変換を対象とする。
- `オリジナル維持` は再圧縮せずコピーする。
- `オリジナル維持` ではリサイズ不可。
- `オリジナル維持` ではメタデータ削除ができない場合がある。
- 明示的な HEIC / HEIF 出力形式は MVP では提供しない。

## 5. UI 制御ルール

- 入力一覧にアニメーション GIF が含まれる場合、JPEG / PNG / WebP / AVIF は出力形式として無効化する。
- 入力一覧に AVIF が含まれる場合、現ビルドでは処理制限の警告・状態表示を行う。
- 処理できない可能性があるファイルは、状態列だけでなくファイル名にも `制約` / `注意` / `失敗` などを表示する。
- 失敗時は結果一覧に対象ファイルと理由を表示する。
- 失敗理由は `anyhow` のエラーチェーン全体 (`{:#}`) を表示する。最外殻の context だけでは真の原因が失われるため。
- 状態列のタグに載せる文言は短く保つ。長文にすると列が横に伸びて他の列が見えなくなるため。
