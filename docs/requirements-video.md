# StorageSlim 動画圧縮モード 要件定義書

最終更新: 2026-08-22
ステータス: 仕様策定中（未実装）

## 1. 目的と適用範囲

このファイルは `動画圧縮モード` の要件を定義します。

- 画像圧縮モードの要件と、両モードに共通する要件は `docs/requirements.md` を参照します。
- 画像側の出力形式マトリクスは `docs/format-matrix.md` を参照します。
- 本ファイルは動画固有の要件と、動画側の対応マトリクスを扱います。

根拠となる決定は `docs/decision-log.md` の `D-17` から `D-20` です。

## 2. モード構成

`D-17` に基づき、画像と動画は同一 UI に混在させず、モードとして切り替えます。

- モードは `画像圧縮モード` / `動画圧縮モード` の 2 種。
- 基本レイアウト（`設定` / `入力と結果`）は両モードで共通。
- 設定項目はモード専用とし、永続化キーも分離する。
  - 画像: `storageslim.settings.v1`（既存）
  - 動画: `storageslim.video.settings.v1`
  - 選択中モード: `storageslim.mode.v1`（既定は画像）
- 共通項目（出力先・上書き・リサイズ基準・タイムスタンプ）もモードごとに独立して記憶する。
- 既定の入出力フォルダは両モードで共通（`<デスクトップ>/@StorageSlim/input|output`）。
- 処理中はモード切り替えを無効化する。
- モードを切り替えても、もう一方の入力一覧と結果はメモリ上に保持する。

## 3. 処理エンジン

`D-18` に基づき、FFmpeg を外部プロセスとして駆動します。

- FFmpeg を Tauri の `externalBin`（sidecar）として同梱し、CLI で呼び出す。
- 同梱するのは LGPL 構成のビルドのみ。`libx264` / `libx265` を含む GPL ビルドは同梱しない。
- FFmpeg バイナリは git 管理対象外とし、`scripts/fetch-ffmpeg.mjs`（`npm run ffmpeg`）で `src-tauri/binaries/` へ配置する。
- 設定で `外部 ffmpeg のパス` を指定できる。指定時は同梱バイナリより優先する。
- 起動時に FFmpeg の存在とバージョンを確認する。利用不可の場合は動画モードで理由を表示し、処理を実行不可にする。
- 入力情報の取得には `ffprobe` を使う。

解決順序:

1. 設定の `外部 ffmpeg のパス`
2. 実行ファイルと同じ階層、およびその `binaries/`
3. `PATH`

`PATH` を最後の手段として残すのは、同梱前でも検証できるようにするため。
実際に選ばれた経路（`setting` / `bundled` / `path`）とエンコーダ名は詳細設定に表示する。

エンコーダ:

| 用途 | Windows | macOS |
| --- | --- | --- |
| H.264 | Media Foundation / NVENC / QSV / AMF | VideoToolbox |
| HEVC（Phase 2） | NVENC / QSV / AMF | VideoToolbox |
| AV1（Phase 2） | SVT-AV1 | SVT-AV1 |
| VP9（Phase 2） | libvpx | libvpx |
| 音声 | AAC / Opus | AAC / Opus |

ライセンス表記:

- `THIRD-PARTY-NOTICES.md` に LGPL 2.1 全文、FFmpeg のバージョン、configure オプション、同一リビジョンのソース入手先を記載する。
- `scripts/generate-notices.mjs` は cargo / npm のみを走査するため、FFmpeg 分は別に管理する。

## 4. 入力仕様

### 4.1 入力方法

画像モードと同一（ファイル追加 / フォルダ追加 / ドラッグ&ドロップ / 入力先フォルダ + 読込）。

### 4.2 対象形式

- `mp4`
- `mov`
- `m4v`
- `webm`
- `mkv`
- `avi`
- `wmv`
- `mts` / `m2ts`

判別は拡張子だけに依存せず、`ffprobe` で映像ストリームの存在を確認する。

### 4.3 取得する情報

入力一覧に表示、または内部判定に使う情報:

- 解像度
- 再生時間
- フレームレート（可変フレームレートかどうかを含む）
- 映像コデック
- 音声コデック / 音声トラックの有無
- ビットレート
- 回転メタデータ
- トラック数
- HDR かどうか

### 4.4 対象外種別の扱い

`D-17` に基づく。

- 動画モードに画像が投入された場合は `skipped` に落とし、理由を `画像圧縮モードで処理してください` とする。
- フォルダ再帰投入時、対象外種別が多数出る場合は 1 件 1 行ではなく `対象外の種別 N 件` として集約表示する。

### 4.5 入力時の警告

処理前に入力一覧へ警告を表示する。

- 再生時間が極端に長い
- 4K 以上の解像度
- HDR（HLG / PQ）
- 可変フレームレート
- 副音声・字幕・チャプターを含む
- FFmpeg が対応していないコデック

## 5. 出力仕様

### 5.1 出力形式

| Phase | コンテナ | 映像 | 音声 |
| --- | --- | --- | --- |
| 1 | MP4 | H.264 | AAC |
| 2 | オリジナル維持 | 入力と同一コデックで再エンコード | AAC |
| 2 | MP4 | HEVC | AAC |
| 2 | WebM | VP9 | Opus |
| 2 | MP4 | AV1 | Opus |

### 5.2 命名と上書き

画像モードと同一の規則を用いる。

- 出力ファイル名は元ファイル名を基準とする。
- 出力形式に応じて拡張子を変更する。
- 上書き許可を選択できる。
- 上書き禁止時に同名ファイルがある場合は連番を付与する。
- 入力フォルダからの相対構造を維持する。

### 5.3 書き出し方式

`D-20` に基づく。

- 動画はメモリ内完結が不可能なため、一時ファイル（`*.part`）へ逐次書き出し、成功時にリネームする。
- 失敗・中断時は一時ファイルを削除し、不完全な出力を残さない。

### 5.4 サイズ増加時の扱い

画像モードと同一。形式・寸法・メタデータのいずれも変えない指定で結果が元より大きくなる場合は、元ファイルをコピーする。削減量は負の値として表示する。

## 6. リサイズ仕様

基準と単位は画像モードと同一（`変更なし` / `幅` / `高さ` / `長辺` x `px` / `%`）。

動画固有の制約:

- アスペクト比は維持する。
- 拡大は行わない。
- yuv420 の制約により、幅・高さは偶数へ丸める。
- `幅 / 高さ / 長辺` 選択時はリサイズ値を必須とする。

## 7. 品質設定

`D-19` に基づく。

### 7.1 品質プリセット

通常 UI では 4 段のプリセットのみを提示する。

- `高画質`
- `標準`
- `小さめ`
- `最小`

内部では、選択中のコデックとエンコーダ経路に応じて指定値へマップする。

| コデック | 高画質 | 標準 | 小さめ | 最小 |
| --- | --- | --- | --- | --- |
| H.264（CRF 対応経路） | 18 | 23 | 28 | 32 |
| VP9 | 28 | 33 | 38 | 43 |
| AV1（SVT-AV1） | 26 | 32 | 38 | 45 |

CRF 非対応のエンコーダ経路（OS / ハードウェアエンコーダ）では、解像度とフレームレートから目標ビットレートを算出する。

各プリセットには結果サイズの目安を併記する（例: `1080p 5 分で約 ◯◯ MB`）。

### 7.2 詳細指定

- 詳細セクションで CRF を直接指定できる。
- CRF 非対応のエンコーダが選択されている場合は無効化し、理由を表示する。

### 7.3 フレームレート

削減効果が大きいため独立した設定項目とする。

- `上限なし`
- `60 fps`
- `30 fps`
- `24 fps`

入力より高い値へは変換しない。可変フレームレート入力は固定フレームレート化し、警告を表示する。

## 8. 音声

- `そのままコピー`
- `AAC で再エンコード`（96 / 128 / 192 kbps）
- `削除`

Phase 1 では先頭の音声トラックのみを対象とする。

## 9. メタデータとストリーム

- メタデータは `削除する` / `保持する` を選択できる。既定は `削除する`。
- **メタデータ削除時も、回転情報（display matrix）は必ず維持する。** 落とすと縦向き動画が横向きで出力される。
- Phase 1 では「先頭の映像 1 本 + 先頭の音声 1 本」のみを出力する。副音声・字幕・チャプターは破棄し、警告に出す。
- HDR のトーンマッピングは対象外。色情報タグは可能な範囲で引き継ぎ、警告を表示する。

## 10. タイムスタンプ

画像モードと同一（作成日時 / 更新日時を個別に引き継ぎ可否選択、既定は OFF）。既存の実装を流用する。

## 11. バッチ処理と進捗

- 入力一覧のファイルを 1 件ずつ順番に処理する。並列化は行わない（FFmpeg 自体がマルチスレッドで動作するため）。
- 1 件失敗しても残りの処理を継続し、成功分は保存する。
- 失敗理由はエラーチェーン全体を表示する。
- 進捗は 2 段で表示する。
  - バッチ全体: `完了数 / 総数`
  - 現在のファイル: `-progress pipe:1` の `out_time_us / duration` から算出した進捗率
- 再生時間に対して不自然に長い処理は、タイムアウト監視の対象とする。

## 12. 停止と一時停止

`D-20` に基づく。

停止:

- FFmpeg の stdin に `q` を送り、コンテナを正しく閉じてから終了させる。
- 一時ファイルを削除する。
- 結果一覧に `中断（出力を破棄しました）` として記録する。
- 停止ボタン付近の文言は `現在のファイルの出力を破棄して停止します` とする。

一時停止:

- Phase 1 ではファイル境界のみ。実行中のエンコードは中断しない。
- ボタン表記は `次のファイルの前で一時停止` とする。
- エンコード中の真の一時停止は将来対応とする。

## 13. UI 要件

- 画像モードの設定パネルの並び（出力 → リサイズ → 品質 → メタデータ → タイムスタンプ → 詳細）を踏襲する。
- 画像側の `デコード上限 (MB)` は動画モードでは表示しない。
- FFmpeg が利用できない場合は、動画モードの実行を不可にし理由を表示する。
- 処理中は停止制御以外の UI 操作を無効化する（モード切り替えを含む）。
- その他のレイアウト要件は `docs/requirements.md` の UI 要件に従う。

## 14. 非機能要件

- 動画処理で UI スレッドをブロックしない。
- FFmpeg のクラッシュがアプリ本体を落とさないこと（別プロセスであることの利点を維持する）。
- macOS では同梱した FFmpeg バイナリも個別に署名し、公証まで確認する。
- インストーラサイズは 40-80 MB 増加する見込み。

## 15. Phase 分け

| Phase | 内容 |
| --- | --- |
| 1 | FFmpeg sidecar 組み込み / `ffprobe` による入力判定 / MP4 H.264 + AAC / 品質プリセット / リサイズ / フレームレート上限 / 音声 3 択 / メタデータ削除（回転維持）/ ファイル内進捗 / `q` による停止と出力破棄 / タイムスタンプ引き継ぎ |
| 2 | WebM VP9・AV1・HEVC 出力 / ハードウェアエンコードの明示選択 / 目標ファイルサイズ指定（2-pass）/ CRF 詳細指定の拡充 |
| 3 | トリミング / 副音声・字幕の保持 / HDR トーンマッピング / サムネイル・GIF 化 / エンコード中の真の一時停止 |

## 16. 対応マトリクス（Phase 1）

| 入力 | MP4 (H.264) |
| --- | --- |
| MP4 (H.264) | 可 |
| MP4 (HEVC) | 可 |
| MOV | 可 |
| WebM | 可 |
| MKV | 可 |
| AVI | 可 |
| WMV | 可 |
| MTS / M2TS | 可 |

Phase 1 の出力は MP4 (H.264 + AAC) のみとし、`オリジナル維持` は提供しない。入力コンテナが何であっても MP4 へ変換される。出力形式が増える Phase 2 で、この表は `docs/format-matrix-video.md` へ分離する。

## 17. 既知制約（実装前の想定）

- `libx264` を使わないため、同一ビットレートでの圧縮効率は x264 に劣る。
- OS / ハードウェアエンコーダの品質は機器構成に依存し、出力結果が環境間で完全一致しない。
- HDR 入力のトーンマッピングは行わない。
- 副音声・字幕・チャプターは Phase 1 では失われる。
- 可変フレームレート入力は固定フレームレート化される。
- エンコード中の一時停止はできない。
- 停止時は現在処理中のファイルの出力を破棄する（画像モードとは挙動が異なる）。
- `externalBin` への登録は未完了。バイナリ未取得の状態でビルドが失敗するのを避けるため、同梱の配線は取得スクリプトの運用が固まってから行う。

## 18. 将来検討

- 複数トラック・字幕の保持
- HDR トーンマッピング
- 動画からサムネイル / アニメーション GIF の生成
- バッチ処理の並列化
