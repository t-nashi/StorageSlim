# StorageSlim 要件定義書

最終更新: 2026-08-12  
ステータス: MVP 開発中

## 1. 目的

StorageSlim は、画像ファイルをクラウド保存・共有・アーカイブの前に、ローカル PC 上で圧縮・リサイズ・形式変換するためのデスクトップアプリです。

初期版では次の役割を 1 つのアプリに統合します。

- リサイズ・クオリティーコントロール
- フォーマット変換
- タイムスタンプ補正
- メタデータ削除

動画圧縮は将来検討とし、現在の MVP 対象外です。

## 2. 対象プラットフォーム

- Windows
- macOS

デスクトップフレームワークは Tauri 2 を採用します。

## 3. 基本方針

- 画像処理はローカルで完結する。
- 外部 API やクラウド処理に依存しない。
- 失敗したファイルがあっても、成功分は保存して処理を継続する。
- 失敗対象と理由を UI で確認できるようにする。
- 処理対象以外の設定はアプリ再起動後も保持する。
- 入力ファイルそのものは既定では上書きしない。

## 4. 入力仕様

### 4.1 入力方法

- ファイル追加
- フォルダ追加
- ドラッグ&ドロップ
- 入力先フォルダ指定 + 読込

### 4.2 フォルダ入力

- フォルダは再帰的に探索する。
- 隠しファイル・システムファイルは対象外にする。
- 出力時は入力フォルダからの相対構造を維持する。

### 4.3 入力先

- 既定値: `<ユーザーのデスクトップ>/@StorageSlim/input`
- UI から任意の入力先フォルダを指定できる。
- 入力先指定は「ファイル追加」「フォルダ追加」とは別管理とし、内容の自動同期は行わない。
- `読込` ボタン押下時に、入力先フォルダ内の処理対象画像を判別して入力一覧へ反映する。

## 5. 出力仕様

### 5.1 出力先

- 既定値: `<ユーザーのデスクトップ>/@StorageSlim/output`
- UI から任意の出力先フォルダを指定できる。
- 既定値へ戻すボタンを提供する。
- 出力先設定はアプリ再起動後も保持する。

### 5.2 出力形式

対応する出力形式は次の通りです。

- オリジナル維持
- GIF
- JPEG
- PNG
- WebP
- AVIF

HEIC / HEIF は、明示的な変換先としては提供しません。入力が HEIC / HEIF で出力形式が「オリジナル維持」の場合のみ、再圧縮せずコピーする方針です。

### 5.3 命名と上書き

- 出力ファイル名は元ファイル名を基準とする。
- 出力形式に応じて拡張子を変更する。
- 上書き許可を選択できる。
- 上書き禁止時に同名ファイルがある場合は連番を付与する。

## 6. 形式対応

入力形式:

- GIF
- JPEG / JPG
- PNG
- WebP
- AVIF
- HEIC
- HEIF

出力形式:

- オリジナル維持
- GIF
- JPEG
- PNG
- WebP
- AVIF

制約:

- アニメーション GIF はアニメーションを保持する。
- アニメーション GIF から JPEG / PNG / WebP / AVIF への変換は初期版では不可。
- AVIF 入力は認識対象だが、現ビルドでは安定性確保のため処理を一時制限している。
- HEIC / HEIF は入力読込に対応し、他形式への変換を対象とする。
- HEIC / HEIF のオリジナル維持はコピー出力とする。

詳細は `docs/format-matrix.md` を参照します。

## 7. リサイズ仕様

リサイズ基準:

- 変更なし
- 幅
- 高さ
- 長辺

リサイズ値:

- px
- %

仕様:

- アスペクト比は維持する。
- 拡大は行わない。
- `幅 / 高さ / 長辺` 選択時はリサイズ値を必須とする。
- リサイズ値が未入力の場合は実行不可にし、入力欄の色で必須状態を示す。

## 8. 品質・圧縮設定

設定項目:

- JPEG: 品質 1-100
- WebP: 品質 1-100
- AVIF: 品質 1-100
- PNG: 圧縮レベル 0-9
- GIF: 色数 2-256

AVIF の speed プリセットは MVP では UI に出さない。品質指定の意味が分かりにくくなるため、現在は `AVIF 品質（1-100）` のみを提供します。

### 8.1 デコード上限

- デコード時に確保を許すメモリ量を 64-8192 MB の範囲で指定できる。
- 既定値は 512 MB。
- 既定値と範囲は UI 上に常時表示する。用途とリスクの補足は画面幅に余裕がある場合のみ表示する。
- 上限を超える入力は、処理前に入力一覧へ必要量の目安を表示する。
- HEIC / HEIF は別デコーダを使用するため適用外。

### 8.2 寸法上限

出力形式ごとに寸法の上限を設け、リサイズ後の寸法で判定する。

| 出力形式 | 上限 | 挙動 |
| --- | --- | --- |
| WebP | 16,383 px | 失敗 |
| JPEG | 65,500 px | 失敗 |
| GIF | 65,535 px | 失敗 |
| AVIF | 65,535 px | 失敗 |
| AVIF | 32,768 px | 警告付き成功 |
| PNG | 制限なし | - |

詳細は `docs/format-matrix.md` を参照します。

## 9. メタデータ

選択肢:

- 削除する
- 保持する

仕様:

- 既定値は `削除する`。
- 保持は形式やライブラリ制約によりベストエフォート。
- HEIC / HEIF のオリジナル維持コピーでは、メタデータ削除と両立しない場合がある。

## 10. タイムスタンプ

対象:

- 作成日時
- 更新日時

仕様:

- それぞれ個別に引き継ぎ可否を選択できる。
- 現在の UI 既定値は OFF。
- 出力ファイル生成後に可能な範囲でタイムスタンプを補正する。

## 11. バッチ処理

仕様:

- 入力一覧のファイルを順番に処理する。
- 1 件失敗しても残りの処理を継続する。
- 成功分は保存する。
- 進捗を `完了数 / 総数` で表示する。
- 失敗件数がある場合は進捗・結果サマリーに表示する。
- 処理中ファイル名を進捗パネルに表示する。
- エンコードはメモリ上で完了させてからファイルを書き出す。失敗時に 0 byte のファイルを残さない。
- 失敗理由はエラーチェーン全体を表示する。
- 出力が元より大きくなった場合は、削減量を負の値として扱い増加を明示する。

処理中操作:

- 一時停止
- 再開
- 停止

停止仕様:

- 現在処理中の 1 ファイルは完了させる。
- 次のファイルへ進む前に停止する。
- エンコード中ファイルを途中破棄しない。

## 12. UI 要件

- 設定パネルは上部に配置する。
- 入力と結果は近い位置に配置する。
- 入力一覧と結果はそれぞれ独立した表パネルにする。
- 表の横スクロール・縦スクロールは各表内で行う。
- 表見出しは縦スクロール時も上部に固定する。
- アプリウィンドウサイズに応じて `入力と結果` パネルと `入力一覧 / 結果` 表領域をストレッチする。
- アプリウィンドウを小さくした場合は、必要に応じてアプリ全体の縦スクロールを許容する。
- 処理中は誤操作防止のため、停止制御以外の UI 操作を無効化する。
- 入力読込中・処理中はローディング表現を表示する。

## 13. 非機能要件

- 画像処理で UI スレッドをブロックしない。
- 大きな画像や複数ファイル処理でもアプリ全体が応答不能にならないようにする。
- AVIF 出力は重い処理であるため、速度確認は release ビルドで行う。
- debug ビルドではログ・クラッシュ確認を優先する。

## 14. 現在の既知制約

- AVIF 入力の処理は現ビルドでは一時制限中。
- 出力形式ごとに寸法上限がある（8.2 参照）。
- 32,769-65,535 px の AVIF は生成できるが、主要ビューア（libavif 系）で開けない。警告を表示する。
- デコードに必要なメモリが上限を超える画像は処理できない。上限は変更可能だが、実メモリを超える値を指定するとプロセスごと終了する。
- アニメーション GIF は合成済みの全面フレームとして出力するため、差分最適化が効かず出力サイズが元より大きくなる場合がある。
- HEIC / HEIF の明示的な HEIC / HEIF 出力は未提供。
- HEIC / HEIF のオリジナル維持はコピー出力であり、リサイズやメタデータ削除とは両立しない場合がある。
- メタデータ保持は完全保証ではない。
- 一時停止 / 停止はファイル単位で反映され、エンコード中の 1 ファイルを即時中断するものではない。

- HEIC / HEIF 出力対応

- より詳細なメタデータ制御
